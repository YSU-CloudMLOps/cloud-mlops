# Week 05 — AI4I 설비 고장 예측 서비스

## 1. 서비스 설계

- **예측 시점:** 센서 수집 시점의 고장 여부를 분류한다. 미래 고장 시점이나 잔여 수명을 예측하는 모델은 아니다.
- **실제 정답:** AI4I 데이터의 같은 행에 있는 `machine_failure`를 사용한다.
- **비교 기준:** 항상 정상(0)으로 예측하는 방법. 테스트 정확도는 96.6%지만 고장 Recall·F1은 0이다.
- **자료 분할:** 학습 8,000건 / 테스트 2,000건. 모델·임계값 선택은 학습 자료 내부의 5-fold 검증으로 진행한다. 기존 테스트셋은 이미 사용한 평가 자료다.
- **필요한 방식:** 우선 함수로 센서 입력 한 건을 예측한다. 외부 앱 연동 시 HTTP, 다수 기록 처리 시 배치로 확장한다.
- **미확인 사항:** 실제 설비에서의 성능, 입력 오류 처리, 응답 시간, 모델 로드 오류 수정 후 재현성.

## 2. 입력과 출력

| 입력 키 | 의미 | 자료형·허용값 | 단위 |
|---|---|---|---|
| `type` | 제품 품질 유형 | 범주형 문자열: `L`(낮음), `M`(중간), `H`(높음) | 없음 |
| `air_temperature_k` | 대기 온도 | 실수, 0 초과 | K |
| `process_temperature_k` | 공정 온도 | 실수, 0 초과 | K |
| `rotational_speed_rpm` | 회전 속도 | 정수, 0 초과 | rpm(회/분) |
| `torque_nm` | 토크 | 실수, 0 이상 | N·m |
| `tool_wear_min` | 공구 마모 시간 | 정수, 0 이상 | min(분) |

제품 유형은 내부에서 L=0, M=1, H=2로 변환한다. 누락·null·숫자 문자열·불리언·NaN·무한대·미등록 유형은 거부한다. 온도는 섭씨가 아닌 K로 입력한다.

| 출력 키 | 자료형·값 | 의미·단위 |
|---|---|---|
| `machine_failure` | 이진 범주형 정수: 0 또는 1 | 0=정상 예측, 1=고장 예측, 무단위 |
| `failure_probability` | 실수: 0~1 | 고장 확률 추정값, 무단위. 0.82는 표시상 82% |

확률이 **0.50 이상이면 고장(1)**으로 판정한다. 예측 성공과 예측 정확성은 별개다.

## 3. 구현 핵심

`predict_failure(payload, model)`에서 입력 검증 → 전처리 → 모델 추론 → 결과 반환 순서로 처리한다.

- 입력 6개를 기존 [전처리](scripts/preprocess.py)·[고도화 전처리](scripts/preprocess_advanced.py)와 동일하게 변환해 17개 피처를 만든다. 열 순서는 [메타데이터](models/advanced_model_metadata.json)의 `feature_names`를 따른다.
- 정답 열(`machine_failure`, `twf`, `hdf`, `pwf`, `osf`, `rnf`)은 입력에서 제외하고, 이 모델에는 RobustScaler를 적용하지 않는다.
- 고도화 LightGBM·XGBoost·Random Forest의 고장 확률을 각각 0.50·0.30·0.20 가중치로 합산한다.
- 모델 오류를 정상 예측(0)으로 바꾸지 않는다.

## 4. 상황별 확인 표

아래는 구현 후 확인할 계획이다. HTTP 상태 코드는 API를 추가할 경우의 설계다.

| 상황 | 예상 응답 | 원인과 고칠 곳 | 수정 후 확인할 증거 |
|---|---|---|---|
| 정상 입력 | 고장 여부·확률 반환 (HTTP 200) | 전처리·열 순서·모델 호출 확인 | 정상·고장 자료 각 3건을 3회 실행해 결과와 재시작 후 일치 확인 |
| 잘못된 입력 | 입력 오류 반환 (HTTP 422) | 누락·자료형·허용값 검증 | 누락, 숫자 문자열, NaN, rpm=0, 유형 X가 모두 거부되는지 확인 |
| 모델 준비 실패 | 모델 사용 불가 오류 (HTTP 503) | 파일 경로·버전·클래스 로딩 수정 | 실패 로그와 복구 후 새 프로세스의 예측 성공 기록 |
| 응답 성공·예측 오차 큼 | 응답은 성공하지만 정답과 불일치 | 데이터 분포·피처·임계값 점검 | 테스트 전체의 혼동 행렬, Precision·Recall·F1·AP를 기준선과 비교 |

## 5. 현재 확인 결과

- **기존 평가 기록:** 고도화 앙상블 임계값 0.50에서 F1 0.8550, AP 0.8974. 이번에 재실행한 성능 수치는 아니다.
- **실제 확인한 오류:** 앙상블 파일 로드 시 `SoftVotingEnsemble` 클래스를 찾지 못했다. 로더 수정과 반복 추론 검증은 미완료다.
- **추가 검증:** 임계값 0.80의 F1 0.88은 테스트셋을 보고 선택한 결과이므로 검증 자료에서 다시 확인해야 한다. 합성 데이터 성능을 실제 설비 성능으로 단정하지 않는다.
